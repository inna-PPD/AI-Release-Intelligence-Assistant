# Синтетичні дефекти: як згенеровано

## Походження
- `defects_synthetic.jsonl` — 20 вигаданих баг-репортів про рішення на Power Platform.
- Автор: Claude (Anthropic), жовтень 2026, за описом робочого контексту (Power Platform, Dataverse, LEO PPM/Gantt, релізи, тестування).
- Жодних реальних даних компанії: компанія, таблиці, флоу, люди і версії вигадані.
- Якщо для витягування використовується теж модель Claude, це треба зазначити в REPORT.md як можливе зміщення: модель може «впізнавати» власний стиль. Щоб цього уникнути, частину даних краще догенерувати іншою моделлю (промпт нижче) і додати справжні issues з GitHub.

## Вигаданий світ
- Компанія: **Contoso** (стандартна вигадана компанія Microsoft).
- Префікс видавця: `cnt_`.
- Таблиці Dataverse: `cnt_request` (заявка на закупівлю), `cnt_approval`, `cnt_invoice`, `cnt_project`, `cnt_projecttask`, `cnt_risk`.
- Застосунки: canvas app «Заявки на закупівлю», model-driven app «Project Hub».
- Флоу: «Approval Flow v2», «LEO Task Sync» (LEO PPM -> Dataverse).
- Інше: plugin `cnt_ApprovalValidation`, PCF `cnt.DateRangePicker`, security role «Project Manager», connection reference `cnt_sharedoffice365`.
- Середовища: DEV / TEST / UAT / PROD. Релізи: 1.4.2 – 1.5.3.

## Які види «брудності» закладено
| Що | Приклади |
|---|---|
| Різна довжина | одне речення (syn-007) ↔ довгий лист (syn-003, syn-017) |
| Змішані мови і суржик | «міссінг депенденсі» (syn-005), UA+EN (syn-010, syn-013) |
| Пропущені поля | немає середовища (syn-003, syn-015), немає версії (syn-002, syn-011) |
| Неформальна мова | емодзі, «пліз», «вроді» |
| Неоднозначна серйозність | «sev: high (було), зараз low» (syn-014) |
| Технічний шум | стектрейс (syn-004), JSON-помилка (syn-019) |
| Не-дефекти | побажання (syn-020), відомий issue з release notes (syn-018) |
| Невпевненість автора | «баг чи так задумано?» (syn-015), «версія вроді 1.5.1» (syn-017) |

Складні випадки (syn-007, syn-013, syn-018, syn-020) варто взяти в golden set: вони добре показують помилки моделей у звіті.

## Промпт для догенерування іншою моделлю
```
Ти — генератор тестових даних. Згенеруй {N} баг-репортів про внутрішнє рішення
на Microsoft Power Platform вигаданої компанії Contoso.

Світ: таблиці Dataverse cnt_request, cnt_approval, cnt_invoice, cnt_project,
cnt_projecttask, cnt_risk; canvas app «Заявки на закупівлю»; model-driven app
«Project Hub»; флоу «Approval Flow v2» і «LEO Task Sync» (синхронізація з LEO PPM);
середовища DEV/TEST/UAT/PROD; релізи 1.4.x–1.5.x.

Вимоги:
- Автори різні: тестувальник (DevOps-шаблон), PM, бухгалтерка, розробник, адмін.
- Канали: email, Teams, Azure DevOps, звіт тест-рану.
- Довжина від 1 речення до 10 рядків.
- Мова: українська, англійська або суміш; суржик; друкарські помилки.
- У ~половини бракує середовища, версії або кроків відтворення.
- 1 з 10 — не дефект (побажання або питання).
- Жодних реальних імен, email, URL, GUID чи назв реальних компаній.

Формат: по одному JSON на рядок:
{"id": "gen-001", "source": "synthetic-<модель>", "channel": "...", "text": "..."}
```
