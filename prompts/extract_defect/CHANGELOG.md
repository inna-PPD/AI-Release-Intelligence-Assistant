# CHANGELOG — extract_defect

## v2 — 2026-10-18
Що змінено і чому (за аналізом помилок v1 на golden set, див. REPORT.md):

| Зміна | Помилка v1, яку виправляємо |
|---|---|
| Пояснено кожне значення `components.type` з прикладами Power Platform | моделі не знали, що таке `alm_tooling`: `pac catalog submit` → `pcf`, `pac solution pack` → `solution`. Описи enum були лише Python-коментарями, яких модель не бачить. `components.type` у v1: 0.10–0.30 |
| «Кожен названий компонент — окремий елемент, таблиця теж» | пропуск явно названих компонентів (`components: []` для «canvas app Заявки на закупівлю»), пропуск таблиць поруч із flow / business rule |
| Правило для `environments`: лише де відтворюється, «на деві все ок» не додавати, середовища клієнтів → `[]` | вигадані середовища (`prod`, `dev`) у GitHub-текстах, додавання `dev` з «на деві все ок» |
| Правило для `severity`: лише явна оцінка або «блокує / критично»; емоції ≠ severity | gpt-4o-mini ставив `high` за тоном тексту без явної оцінки |
| Приклади неявної регресії («з 12.10 перестало», «у старій версії працює») | пропуск `is_regression: true` для неявних формулювань |
| Правила для `release_version`, `steps_to_reproduce`, `expected_result`, мова оригіналу | узгодження з `data/golden/ANNOTATION_GUIDE.md` |

Ризик: правила виведено з помилок на тих самих 10 текстах golden set, тож приріст точності може бути трохи завищеним. Тому приклади в промпті навмисно взято не з golden set (жодних «на деві все ок», «з 12.10», назв flow чи версій з еталону), а v2 додатково перевіряється вибірково на текстах поза golden set.
